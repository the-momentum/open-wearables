**Settings → Priorities** decides which data source is shown when more than one source has data for the same period. This matters as soon as a user connects several providers or wears several devices from the same provider.

## Provider Priorities

Use the arrows to reorder the list, then click **Save Changes**. Higher in the list means higher priority.

The list contains every supported provider from the start, seeded with a default order when the API boots. Providers added in a later release are appended below the ones you have already ordered, so an upgrade never reshuffles your configuration.

How it works:

- When data from multiple providers overlaps in time, the higher-priority provider's data is shown.
- Within the same provider, watch data is preferred over phone data by default. You can change that below.

## Device Type Priorities

The second list orders device types within a single provider: **Watch**, **Band**, **Ring**, **Phone**, **Scale**, **Other**, and **Unknown**. When the same provider delivers data from two devices, the higher-priority device type wins.

Reorder with the arrows and click **Save Changes**. The two lists are saved independently.

## Applying Priorities in the API

Sleep, workout and timeseries endpoints return every source by default. Pass `filter_by_priority=true` (default `false`) to apply the order above:

- **Sleep** keeps only the highest-priority source's sessions per night.
- **Timeseries** keeps the highest-priority source per series type.
- **Workouts** drop a workout when a workout from a higher-priority source overlaps at least half of its duration, such as a Withings copy of an Apple Watch workout. Workouts that nothing overlaps are kept, as are back-to-back sessions and workouts from equally ranked sources. The same filter applies to `/events/workouts/totals`.

The workout overlap threshold is set with the `WORKOUT_DUPLICATE_OVERLAP` environment variable, a share of the lower-priority workout's duration between 0 and 1 (default `0.5`).

The MCP server always requests priority-filtered workouts and timeseries.
