**Settings → Change Password** updates the password of the developer account you are signed in with. You cannot change another developer's password from the developer portal.

1. Enter your **Current Password**.
2. Enter a **New Password** of at least 8 characters.
3. Repeat it in **Confirm New Password**.
4. Click **Update Password**.

On success the form clears and a "Password updated successfully" toast appears. The form refuses to submit when the new password is shorter than 8 characters or the confirmation does not match. If the current password is wrong, the backend rejects the request and the toast shows "Incorrect current password".

<Tip>
The first developer account is seeded with the value of `ADMIN_PASSWORD` from the environment. Changing `ADMIN_PASSWORD` later does not update an existing account, so change the password on this page instead. For an account that still uses the public default password, see [Default password prompt](#default-password-prompt) below.
</Tip>

## Default password prompt

With `ENVIRONMENT=production` signing in with the public default password (`your-secure-password`) is refused, and the login page explains how to replace it: on the backend set `ADMIN_EMAIL` to that account's email and `ADMIN_PASSWORD` to a new password, then restart it. Only the account whose email matches `ADMIN_EMAIL` is updated. On startup the backend changes the `ADMIN_EMAIL` account's password to `ADMIN_PASSWORD` and revokes its refresh tokens, so you can then sign in with the new password. Access tokens issued before that stay valid until they expire (`ACCESS_TOKEN_EXPIRE_MINUTES`, 60 minutes by default).

In any other environment signing in with the default opens a **Change the default password** page instead of the dashboard. You can click **Not now** and continue, and the page comes back at the next sign-in.
