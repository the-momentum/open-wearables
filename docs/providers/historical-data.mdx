This page documents how far back historical data can be backfilled from each provider - the maximum range a historical sync can request.

Use it to compare providers when planning an integration. For the full list of data types per provider, see the [Coverage Matrix](/providers/coverage).

## Maximum Historical Range

**Max range** is the furthest point in the past from which a provider allows historical data to be backfilled.

| Provider | Max range | Remarks |
|---|---|---|
| Garmin | 30 days | Limited to 30 days before the user's connection (consent) date. Requires the `HISTORICAL_DATA_EXPORT` permission. One backfill request per user per timeframe - reconnect to request again. |
| Oura | No limit | |
| Whoop | No limit | |
| Ultrahuman | No limit | |
| Strava | No limit | |
| Fitbit | No limit | |
| Polar | 365 days | Hard API limit - requests with a `from` date older than 365 days are rejected (`400 "Value for from cannot be older than 365 days"`). Data is also only available from the user's consent date onward. |
| Suunto | No limit | |
| Google Health Connect | 30 days | Health Connect only exposes the last 30 days to apps that lack the `READ_HEALTH_DATA_HISTORY` permission, which the Open Wearables SDK does not currently request. |
| Google Health API | No limit | |
| Apple Health | No limit | |
| Samsung Health | No limit | |

Several APIs cap how much data a *single request* may cover even when there is no lookback limit - Suunto to a 28-day window, the Google Health API to 14 or 90 days depending on the data type, Fitbit to 24 hours for intraday endpoints. Open Wearables splits historical syncs into compliant chunks automatically, so these caps affect how long a backfill takes, not how far back it reaches.

<Note>
  **Apple Health and Samsung Health** have no backend-enforced historical limit today. How far back to sync is decided on the device by the mobile SDK, and the backend ingests whatever the SDK pushes. Backend-side control over the historical range for these providers will be added in the future.
</Note>
